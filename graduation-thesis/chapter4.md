
# 第四章 系统实现

## 4.1 后端实现

### 4.1.1 项目结构

后端项目采用模块化的目录结构，主要包括以下几个部分：

`config` 目录包含数据库配置文件，使用 dotenv 管理环境变量，配置数据库连接信息。

`controllers` 目录包含各个功能模块的控制器，负责处理 HTTP 请求和响应，包括用户控制器、物品控制器、订单控制器、消息控制器、纠纷控制器等。

`models` 目录包含数据模型定义，使用 Sequelize ORM 定义数据库表结构和关联关系，包括用户模型、物品模型、订单模型、消息模型、纠纷模型等。

`routes` 目录包含路由定义，将 HTTP 请求映射到相应的控制器方法，包括认证路由、用户路由、物品路由、订单路由、消息路由、纠纷路由等。

`services` 目录包含业务逻辑层，处理复杂的业务逻辑，如订单提醒服务、信用服务、纠纷处理服务等。

`middleware` 目录包含中间件，用于处理请求前的验证和处理，如认证中间件、错误处理中间件等。

`scripts` 目录包含数据库初始化和数据迁移脚本，用于初始化测试数据和执行数据库迁移。

### 4.1.2 核心模块实现

用户认证模块实现了用户注册、登录、token验证等功能。注册时对用户输入进行验证，使用 bcrypt 对密码进行加密存储。登录时验证用户身份，生成 JWT token 返回给客户端。认证中间件验证请求中的 token，确保用户已登录。

物品管理模块实现了物品的发布、编辑、删除、搜索等功能。物品发布时需要上传图片，使用 multer 中间件处理文件上传，将图片存储在服务器指定目录。物品搜索支持按关键词、分类、价格等条件进行筛选。

订单管理模块实现了订单的创建、查看、状态更新等功能。订单创建时自动生成订单编号，计算租金和押金金额。订单状态流转包括待确认、已确认、使用中、已归还、已完成、已取消等状态。系统会定时检查订单状态，发送订单提醒消息。

消息模块实现了用户之间的即时通讯功能。消息存储在数据库中，支持文本和图片消息。消息发送时会记录发送者、接收者、物品关联等信息，方便后续查询和展示。

纠纷处理模块实现了纠纷的申请、举证、仲裁等功能。用户可以针对订单提交纠纷申请，双方可以提交证据陈述。管理员可以查看纠纷列表，根据证据进行仲裁，给出处理结果。

### 4.1.3 数据库配置

数据库配置使用 Sequelize ORM，支持 MySQL 数据库。数据库连接信息通过环境变量配置，包括数据库主机、端口、用户名、密码、数据库名等。

数据库模型定义了各个表的结构和字段，包括用户表、物品表、订单表、消息表、纠纷表等。模型之间通过外键关联，如用户与物品的一对多关系、订单与物品的一对一关系等。

数据库同步时使用 `alter` 模式，允许在不删除现有数据的情况下修改表结构。系统启动时会自动执行数据库同步操作，确保表结构与模型定义一致。

## 4.2 移动端实现

### 4.2.1 项目结构

前端项目基于 uni-app 框架开发，采用 Vue 3 + TypeScript 的技术栈。项目结构主要包括以下几个部分：

`pages` 目录包含各个页面组件，包括首页、物品详情页、发布页、订单页、消息页、个人中心页等。每个页面对应一个目录，包含页面组件和相关资源。

`components` 目录包含可复用的组件，如物品卡片、订单卡片、消息列表项、导航栏等。组件设计遵循单一职责原则，便于复用和维护。

`api` 目录包含 API 请求封装，使用 axios 封装 HTTP 请求，统一处理请求和响应。API 模块按功能划分，包括认证 API、物品 API、订单 API、消息 API、纠纷 API 等。

`stores` 目录包含状态管理模块，使用 Pinia 管理全局状态，包括用户状态、订单状态、消息状态等。状态管理模块提供响应式的数据访问和修改方法。

`utils` 目录包含工具函数，包括请求封装、图片处理、日期格式化、设备信息获取等工具函数。

`static` 目录包含静态资源，包括图片、图标、样式文件等。

### 4.2.2 核心页面实现

首页展示推荐物品列表，采用瀑布流布局，支持下拉刷新和上拉加载更多。顶部设有搜索框和分类导航，用户可以快速搜索和筛选物品。物品卡片展示物品图片、名称、价格和发布者信息，点击卡片可进入物品详情页。

物品详情页展示物品的详细信息，包括多张图片轮播、物品描述、价格、押金、交易类型等。用户可以发起租赁请求、收藏物品或联系卖家。租赁请求需要选择租赁时间，确认订单信息后提交。

发布页提供物品发布表单，用户需要填写物品名称、描述、分类、价格、押金等信息，并上传物品图片。表单验证确保必填字段完整，图片格式符合要求。

订单列表页按状态分类展示用户的订单，包括待确认、使用中、已完成、已取消等状态。用户可以点击订单查看详情，进行确认、取消、评价等操作。

消息中心页展示用户的消息列表，支持按会话分组显示。用户可以查看未读消息数量，点击会话进入消息详情页进行沟通。消息详情页支持实时发送和接收消息，消息状态实时更新。

个人中心页展示用户的基本信息，包括头像、昵称、诚信分、学校、专业等。提供发布物品、查看订单、消息中心、收藏列表、设置等入口。用户可以修改个人信息、修改密码、退出登录。

### 4.2.3 状态管理与路由

状态管理使用 Pinia，将全局状态按模块划分，包括用户状态、订单状态、消息状态等。每个状态模块提供 getter、action 和 mutation，实现响应式的数据管理。

路由配置在 pages.json 文件中，定义了各个页面的路径、样式和 tabBar 配置。tabBar 包含首页、订单、发布、消息、个人中心五个入口，方便用户快速切换。

路由跳转使用 uni-app 提供的 API，支持页面跳转、参数传递、页面返回等操作。页面间的数据传递通过 URL 参数或全局状态管理实现。

## 4.3 模块实现

### 4.3.1 用户模块

用户模块实现了用户注册、登录、个人信息管理等功能。用户注册时需要填写用户名、密码、手机号等信息，系统对输入进行验证，确保信息完整和格式正确。密码使用 bcrypt 加密存储，保障用户密码安全。

用户登录支持手机号或用户名登录，验证通过后生成 JWT token，返回给客户端存储。认证中间件验证请求中的 token，确保用户已登录才能访问需要认证的接口。

个人信息管理允许用户修改头像、昵称、学校、专业等信息。头像上传使用 uni-app 的上传 API，将图片上传到服务器并更新用户信息。

### 4.3.2 物品模块

物品模块实现了物品的发布、浏览、搜索、详情查看等功能。物品发布需要填写物品名称、描述、分类、价格、押金等信息，并上传物品图片。物品图片支持多张上传，使用 multer 中间件处理文件上传。

物品浏览支持分页展示，首页展示推荐物品列表。物品搜索支持按关键词、分类、价格范围等条件进行筛选，使用 Sequelize 的查询方法实现复杂查询。

物品详情展示物品的完整信息，包括图片轮播、描述、价格、押金、交易类型、发布者信息等。用户可以发起租赁请求、收藏物品或联系卖家。

### 4.3.3 订单模块

订单模块实现了订单的创建、查看、状态更新等功能。订单创建时需要选择租赁时间，系统自动计算租金和押金金额。订单创建后发送消息通知卖家，卖家可以确认或拒绝订单。

订单状态流转包括待确认、已确认、使用中、已归还、已完成、已取消等状态。用户可以查看自己的订单列表，按状态筛选订单。订单详情展示订单的完整信息，包括物品信息、租赁时间、金额、双方信息等。

订单提醒服务定时检查订单状态，在订单即将到期时发送提醒消息给用户，提醒用户及时归还物品。

### 4.3.4 消息模块

消息模块实现了用户之间的即时通讯功能。消息发送支持文本和图片格式，消息存储在数据库中，记录发送者、接收者、物品关联等信息。

消息列表按会话分组显示，支持查看未读消息数量。消息详情页实时显示消息内容，支持发送和接收消息。消息状态实时更新，已读消息标记为已读状态。

### 4.3.5 纠纷模块

纠纷模块实现了纠纷的申请、举证、仲裁等功能。用户可以针对订单提交纠纷申请，填写纠纷原因并上传证据图片。纠纷申请提交后，系统通知被申请人进行回应。

被申请人可以查看纠纷详情，提交自己的陈述和证据。管理员可以查看纠纷列表，根据双方提供的证据进行仲裁，给出处理结果。

纠纷处理结果包括责任判定、损失金额、诚信分扣减等。处理结果会通知双方用户，同时更新相关用户的诚信分和订单状态。
